# 场景字段与维护规则

## 字段

| 字段 | 用途 |
|---|---|
| scene_id | 稳定唯一 ID，创建后不随名称变化 |
| scene_name | 用户能直接理解的场景名称 |
| category | 所属全流程大类 |
| stage | 开店阶段 |
| goal | 用户当前生意目标 |
| business_form | 适用经营形态 |
| object | 商品、位置、物料、顾客、库存或内容 |
| channel | 现场、地图、朋友圈、短视频、社群等 |
| trigger | 用户何时需要该场景 |
| inputs | 必须提供的真实材料或数据 |
| steps | 3—7 个行动步骤 |
| output | 场景完成后的可用结果 |
| done_rule | 可观察的完成标准 |
| skip_rule | 允许跳过的事实条件 |
| next_scene | 完成后的推荐场景 |
| status | 首期可用、规划中、待验证或已下线 |
| priority | P0、P1 或 P2 |

## 状态与跳过

- 未开始：尚未进入。
- 进行中：已经开始但没有满足完成标准。
- 已完成：已有可核验结果。
- 跳过：当前路线不需要，或用户已有可靠结果。

跳过不能删除节点历史。用户可以随时重新评估。

## 优先级

- P0：首期闭环必须存在，直接影响能否开起来并验证。
- P1：高频长尾，能显著改善成交、成本或复购。
- P2：季节、活动或特定经营形态使用。
