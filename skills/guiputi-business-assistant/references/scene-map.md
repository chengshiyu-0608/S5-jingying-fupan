# 开店全流程场景地图

> 版本：v0.2 · 更新时间：2026-09-30
> 产品对象：小微经营者 · 首期形态：流动摊位、固定摊位

## 文档用途

这份地图用于统一三件事：

1. 场景库如何分类和导航。
2. 哪些场景首期必须做，哪些场景先进入长尾目录。
3. 后续 PRD、原型和场景清单使用什么共同字段。

## 一、产品定位与边界

### 1.1 产品定位

> 帮助小微经营者把“想开店”推进到“开起来、卖出去、知道下一步怎么改”。

### 1.2 经营形态

| 层级 | 经营形态 | 说明 |
|---|---|---|
| 首期 | 流动摊位 | 重点验证选品、选址、试营业和现场经营 |
| 首期 | 固定摊位 | 增加物料、规则、复购和稳定经营场景 |
| 后续 | 小门店 | 扩展房租、员工、库存、会员和门店运营 |
| 后续 | 上门 / 线上经营 | 按服务交付、预约、内容获客等方向扩展 |

### 1.3 首期边界

**首期要做**：路线引导、场景检索、行动卡、材料入口、节点状态、经营记录和复盘。
**首期暂不做**：复杂项目管理、多人协作、多店权限、重型 ERP、企业级审批。

## 二、场景导航总模型

```text
经营形态
  → 开店阶段
    → 生意目标
      → 经营动作
        → 小场景
          → 行动卡
```

### 示例

```text
固定摊位
  → 开店准备
    → 找到可行位置
      → 选址与人流调研
        → 下班口观察 15 分钟
          → 记录经过人数、停留人数、竞品和结论
```

### 场景节点状态

| 状态 | 含义 | 对用户的作用 |
|---|---|---|
| 未开始 | 尚未进入 | 作为待办候选 |
| 进行中 | 已开始但未达成完成标准 | 继续当前行动 |
| 已完成 | 已有可核验结果 | 推荐下一场景 |
| 跳过 | 当前不需要或已有可靠结果 | 直接进入后续场景 |

“跳过”不删除历史，节点应保留“重新评估”入口。

## 三、开店全流程地图

### 3.1 四个阶段分组

| 阶段组 | 目标 | 包含阶段 |
|---|---|---|
| A. 想清楚 | 确定做什么、是否值得开始 | 1 生意方向 |
| B. 准备好 | 把品、点、规则、物料准备到可试卖 | 2—7 选品、选址、合规、采购、物料、开业准备 |
| C. 卖起来 | 用一次低成本试营业验证事实 | 8—10 试营业、成交、宣传 |
| D. 做得更好 | 用数据复盘并决定下一步 | 11—14 日常经营、复盘、活动、调整扩展 |

### 3.2 14 个流程阶段

| 编号 | 流程阶段 | 用户要解决的问题 | 主要场景大类 | 首期策略 |
|---:|---|---|---|---|
| 01 | 生意方向与开店决策 | 做什么、卖给谁、是否值得开始 | 生意方向与开店决策 | 先做目标确认，长尾目录 |
| 02 | 选品、菜单与定价 | 卖什么、多少钱不亏 | 选品、菜单与定价 | 首期开放 |
| 03 | 选址与人流调研 | 哪里有人、能不能摆、竞品如何 | 选址与人流调研 | 首期开放 |
| 04 | 证照与经营规则 | 需要什么材料、找谁办理 | 办事与合规 | 首期提供材料入口，细化后续扩展 |
| 05 | 供应商、采购与库存 | 从哪里买、买多少、如何减少损耗 | 供应商、采购与库存 | 先做成本和记录，长尾扩展 |
| 06 | 门头、LOGO 与摊位物料 | 如何让路人快速看懂并愿意停留 | 门头、LOGO 与物料 | 首期开放海报、菜单、价签 |
| 07 | 开业前准备 | 开张前还缺什么 | 开业前准备 | 用开张清单承载 |
| 08 | 试营业与现场验证 | 有人买吗、哪里卡住 | 试营业与现场验证 | 首期开放 |
| 09 | 顾客接待与成交 | 怎么招呼、报价、处理异议 | 顾客接待与成交 | 长尾目录，后续开放 |
| 10 | 内容与本地宣传 | 如何让附近的人知道 | 内容与本地宣传 | 先做动作索引，后续开放 |
| 11 | 每日经营与补货 | 如何补货、减少损耗、保持稳定 | 日常运营 | 先接经营记录 |
| 12 | 数据分析与经营复盘 | 明天继续、调整、换品还是换点 | 数据分析与复盘 | 首期开放 |
| 13 | 活动与季节性经营 | 节日、天气、淡旺季如何应对 | 活动与季节性经营 | 长尾目录 |
| 14 | 调价、换品、换点与扩展 | 何时改变或扩大经营 | 调整与增长 | 长尾目录 |

## 四、场景库信息架构

### 4.1 首页入口

首页只放高频和个性化入口，不平铺几千个场景：

1. 今天先做什么
2. 继续上次动作
3. 最近使用
4. 我的收藏
5. 按经营目标找
6. 按开店阶段找
7. 搜索全部场景

### 4.2 场景库页面

| 区域 | 主要内容 |
|---|---|
| 顶部 | 经营形态切换、搜索框、最近使用 |
| 左侧 | 阶段、目标、对象、渠道、状态筛选 |
| 中间 | 按经营动作分组的场景列表，分页或懒加载 |
| 右侧 / 详情页 | 所需材料、行动步骤、完成标准、跳过条件、关联场景 |
| 行动卡 | 每次只展示 1—3 个当前最值得做的动作 |

### 4.3 筛选维度

```text
阶段：想法 / 准备 / 试营业 / 稳定经营 / 复盘 / 调整
目标：选品 / 选址 / 获客 / 成交 / 降本 / 合规 / 复购
对象：商品 / 位置 / 物料 / 顾客 / 库存 / 内容 / 材料
渠道：现场 / 地图 / 朋友圈 / 短视频 / 小红书 / 社群
状态：未开始 / 进行中 / 已完成 / 跳过
```

## 五、长尾场景建设规则

### 5.1 组合公式

不手工堆几千张孤立卡片，使用组合规则生成可检索的长尾场景：

```text
经营形态 × 开店阶段 × 生意目标 × 经营对象 × 渠道 × 限制条件
```

### 5.2 长尾示例

| 经营形态 | 阶段 | 目标 | 对象 | 渠道 | 限制条件 | 生成的小场景 |
|---|---|---|---|---|---|---|
| 固定摊位 | 开业前 | 获客 | 海报 | 线下路过 | 夜间灯光不足 | 夜间远距离可读的推车海报 |
| 流动摊位 | 试营业 | 控制成本 | 原料 | 现场经营 | 预算有限 | 低库存半天试营业备货 |
| 小门店 | 稳定经营 | 增加复购 | 顾客 | 朋友圈 | 没有会员系统 | 无会员系统的复购提醒 |

### 5.3 场景状态分层

- **首期可用**：已经定义流程、输入、输出和完成标准。
- **待验证**：已有用户需求，但还没有完成真实测试。
- **规划中**：已进入目录，尚未开放完整执行链路。
- **已下线**：不再推荐，但保留历史记录。

规划中的场景不能在界面上伪装成已经可执行的功能。

## 六、首期必须可用的场景

首期形成一个最小闭环：

```text
选品与算账
  → 选址与人流调研
    → 海报与摊位物料
      → 试营业
        → 事后经营分析
          → 下一次调整
```

| 场景 | 最小输出 | 完成判断 |
|---|---|---|
| 选品与算账 | 单品账、毛利、保本单量 | 用户能说清售价、单份毛利和保本量 |
| 选址与人流调研 | 候选点比较结论 | 至少完成候选点和时段观察 |
| 海报与摊位物料 | 海报、菜单、价签文案 | 路人能快速看懂品名和价格 |
| 试营业 | 半天试营业清单与记录 | 完成一次低成本试卖 |
| 事后经营分析 | 经营记录与下一步行动 | 能根据销量、客单、成本或反馈决定一个调整动作 |

首期之外的场景进入目录，标记为“待验证”或“规划中”。

## 七、场景卡标准模板

每个可执行场景都要回答以下问题：

```text
场景名称：用户能直接理解的动作 + 对象
适用形态：流动摊位 / 固定摊位 / 小门店 / 其他
触发时机：用户什么时候会需要它
需要材料：用户需要提供什么真实信息
行动步骤：3—7 步，能被执行
输出结果：清单 / 文案 / 比较表 / 判断 / 行动卡
完成标准：什么算完成
跳过条件：已有什么可靠结果时可以跳过
下一场景：完成后推荐什么
状态：首期可用 / 待验证 / 规划中 / 已下线
优先级：P0 / P1 / P2
```

## 八、下一步建设计划

| 顺序 | 工作 | 产出 | 验收方式 |
|---:|---|---|---|
| 1 | 建立代表性样本 | 100—200 条场景清单 | 字段完整、无重复 ID |
| 2 | 验证导航 | 5—8 名个体经营者测试分类和搜索词 | 能在 30 秒内找到目标场景 |
| 3 | 确定首期范围 | P0 场景清单 | 每个场景有输入、输出、完成标准 |
| 4 | 编写 PRD v0.1 | 产品需求文档 | 原型、场景清单、状态规则一致 |
| 5 | 更新原型 | 搜索、筛选、收藏、继续、跳过 | 关键路径可点击跑通 |
| 6 | 扩充长尾 | 按组合公式持续增加场景 | 新场景不破坏已有导航和 ID |

## 九、与场景清单的对应关系

场景清单至少维护以下字段：

| 字段 | 用途 |
|---|---|
| `scene_id` | 稳定唯一 ID，创建后不随名称变化 |
| `scene_name` | 用户能直接理解的场景名称 |
| `category` | 所属大类 |
| `stage` | 开店阶段 |
| `goal` | 生意目标 |
| `business_form` | 适用经营形态 |
| `object` | 商品、位置、物料、顾客、库存等 |
| `channel` | 现场、地图、朋友圈、短视频、社群等 |
| `trigger` | 用户什么时候会需要它 |
| `inputs` | 需要用户提供的材料 |
| `steps` | 行动步骤 |
| `output` | 最终产出 |
| `done_rule` | 什么算完成 |
| `skip_rule` | 什么情况下可以跳过 |
| `next_scene` | 完成后推荐什么 |
| `status` | 首期可用、待验证、规划中、已下线 |
| `priority` | P0、P1、P2 |

场景清单是详细记录，场景地图是导航和范围定义；两者不要互相替代。
