# 场景库接口实测手册

> **2026-09-29 全量实测**（拉完整库 72,016 条）。照这份做能省一次返工。
> 底库：`https://www.gpt.com.cn/api/scenes`（公开、无需登录）。

## 一、量级：先知道要拉多少

| 项 | 实测值 |
|---|---|
| 全库场景数 | **72,016** |
| `limit` 上限 | **1000**（传 1000 就拿 1000，不报错） |
| 拉全量 | **73 次请求 / 约 162 秒 / 约 50 MB**（只留必要字段） |
| `paging.total` / `summary.matchedScenes` | 都等于 72,016 |

⇒ **只拉一次、落本地 JSON 复用**。一次全量约 2.7 分钟，跑第二遍纯属浪费。

## 二、⚠️ 会被静默忽略的参数

下面这几个传了**不报错、也不生效**，返回的仍是默认全集（实测返回逐条一致）：

```
category=business   ❌ 无效      cat=business    ❌ 无效
sort=hot            ❌ 无效      homepage_hot=1  ❌ 无效
```

⇒ **服务端没有任何筛选能力，必须全量拉下来本地过滤。** 照字面以为能服务端过滤 → 少拉数据还当成筛过了，是最容易踩的坑。

## 三、找单个场景：两个端点的返回结构不一样

| 端点 | 返回结构 | 场景对象在哪 |
|---|---|---|
| `/api/scenes/<slug>` | `{source, scene, generatedSpec}` | **`scene` 键**（不在 `items`！） |
| `/api/scenes?slug=<slug>&limit=1` | `{device, items, source, paging, summary}` | `items[0]` |
| `/api/scene/<slug>`（单数） | HTTP 404 | —— |

⇒ 想统一按 `items` 处理就用**第二个**；用第一个要记得读 `scene`。

## 四、关键词搜索

`/api/scenes?q=<关键词>`

- **固定返回 8 条**，`limit=200` 也还是 8 条（实测 3 组关键词一致）。
- 返回结构与列表接口一致（`items`），但 `paging` / `summary` 为空。
- `q` 的排序**与 `match_scene` 的召回排序经常相反** —— 绑事项看 `match_scene`，别用 `q` 命中。

## 六、其他可用字段

| 字段 | 取值 | 怎么用 |
|---|---|---|
| `identity_tags` | 职能标签：`demand_analyst` `process_engineer` `new_media_operator` `ecommerce_operator` `private_domain_ops` `market_specialist` `brand_manager` …（或 `agent_gap`） | **聚簇**：同一批职能标签的场景天然成簇，能直接拼一个岗位/一件事 |
| `outputs` | `text` / `xlsx` / `png` / `docx` / `report` / `pptx` / `image_prompt` … | **判交付物形态**。文案类事项**别绑 `outputs=['png']` 的出图场景** |
| `risk_level` | `low` 40,787 / `medium` 20,967 / `high` 10,262 | 高风险的慎选 |
| `price` | 全为 0 | 无区分度 |
| `user_expressions` | 见下节 | 「用户常这么说」的**唯一合法来源** |

## 七、`user_expressions`（「用户常这么说」的来源）

**条数分布（business 线）**：

| 条数 | 场景数 |
|---|---|
| 6 | **10,273**（最多） |
| 3 | 3,065 |
| 5 | 429 |
| 8 | 187 |
| 4 | 8 |
| 2 | 5 |
| **0** | **8** |

全库有 **103 个场景的 `user_expressions` 是空数组**（business 里例如 `video-shop-visit` 写探店视频脚本、`biz-9` 战略规划、`dp-yjs-32` 注销公司一件事）。

⇒ 三条口径：

1. **来源常见是 6 条不是 3~4 条** —— 是「从 6 条里挑 3~4 条」，不是「通常只有 3~4 条」。
2. **遇到空数组要有兜底**：从该场景的 `user_task` 自拟 3 条口语问法，并在交付里**标注"自拟"**（别冒称官方原话）。
3. **同一批事项会混两种语气**：`ag-*`（agent_gap 那批）的原话是长书面句（「帮我写一份会员运营方案，重点是怎么提高复购率。」），`leaf-*` 的是超短口语（「不知道每天发啥了」「群越来越冷，想搞个活动热闹一下」）。**交付前统一一遍**：短句补主语、长句砍到 ≤20 字，否则「用户常这么说」一栏一长一短没法看。

```json
{
  "scene_id": "scene_f11943ea-b825-44",
  "slug": "biz-sell-copy",
  "title": "写卖货文案",
  "url": "/scene/biz-sell-copy/",
  "type": "scene",
  "category": "business",
  "category_title": "做生意",
  "user_task": "以卖货文案操盘手…（长文，含要求与风险边界）",
  "description": "简称",
  "keywords": ["差评回复", "差评处理", "回复", "文字"],
  "input_modes": ["text", "segmented", "checkbox", "..."],
  "outputs": ["text"],
  "price": 0,
  "risk_level": "low",
  "priority": 100,
  "delivery_methods": ["copy_prompt", "platform_generate", "result_package"],
  "homepage_hot": false,
  "hot_label": "乡村",
  "generated_spec_id": null,
  "user_expressions": ["…", "…"],
```
