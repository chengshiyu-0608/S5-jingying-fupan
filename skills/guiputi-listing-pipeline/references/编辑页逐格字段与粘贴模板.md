# 编辑页逐格字段与粘贴模板

> 用途：`con.gpt.com.cn` → 发布中心 → 创建技能/专家（`/publish/new?view=skill`）。
> **格子清单与规格是 2026-09-29 从页面实读 + 历史交付里核出来的**；页面改版时以你眼前的为准。
> 页面上的**灰字只是示例、不会进包**（页面自己就写着这句）——要用必须自己打字进去。

## 〇、动手前先看三处

**一、非内容格先确认，别当成内容格瞎填。**

| 格 | 口径 |
|---|---|
| 挂在哪个 MCP 服务器上 | 一律「硅菩提 MCP 服务（密钥版）」；末尾「未提交」按页面提示处理 |
| 挂在哪个主体下 | 发布后资产归属这个主体 → **必须问用户** |
| 路径名（包名 `source`） | `guiputi-` + 功能英文，全平台唯一；**改它等于另建包**，一律不改 |
| 版本号 | 未提交 `1.0.0`；已提交升一版；**该版号已被平台登记过就跳过** |
| 服务类目 | 固定「工具 → 办公」 |
| 市场展示分类 | 与包内 frontmatter `category` **必须同值**（生意线＝商业运营，办公行政线＝办公协同） |

**二、上下必须自洽。** 能力介绍 / 触发短词 / 试试这样问我 / 英文 4 格，**全是照着常办事项生成的**。事项一改，这 8 格全部重写。

**三、先数常办事项够不够。** 规则栏写「**5–30 个为宜**」，只有 3 条就是低于下限；再逐条看**它跟包名是不是同一件事**（实测坑：包名「朋友圈社群运营」，事项里却塞了「反馈与排期（开发排期）」「店面介绍词（店铺首页）」——一个是产品需求排期、一个是门店展陈，跟包名完全不是一件事）。

## 二、常办事项（下半页第一格）

**操作**：先一条一条删掉旧的（每行右侧有删除），再按表重录 —— **左边输入框手打事项名**，右边「用户常这么说」整段粘，再点那一行的「**找场景**」用第三列的词搜出第四列的场景。**每条录完点一次「试卡」**，看一眼确认卡像不像样再往下走。

**交付给用户的表，必须是这五列**：

| # | 事项名 | 场景名称 | scene_id | 召回位次 | 用户常这么说（整段粘） |
|---|---|---|---|---|---|
| 1 | `≤5 字` | 库里那个场景的全名 | `scene:<slug>` | 第 N | 3~4 句原话，用「、」分隔 |

**五条口径**：

1. **事项名 ≤5 字**（页面规则栏写 ≤6 字，按 5 字收口），5–30 个。事项名本身也是搜索面，一律用高频短词，别用长句。
2. **「用户常这么说」抄 `user_expressions` 原话**：`GET https://www.gpt.com.cn/api/scenes?q=<词>`（固定返回 8 条）或单场景 `/api/scenes/<slug>`。**别抄场景详情页方括号里的材料清单**——那是出卡要收集的材料，不是这一格。
3. **长句照抄**，不要改写压缩；多条用「、」、**段内不折行**。原话不足 3 条的有几条用几条，别硬凑。
4. **绑哪个场景看 `match_scene` 召回位次，不看 `?q=` 搜索命中**（两套排序常相反）。前 2 稳、3~5 要跑一轮看、**掉出前 6 基本必挂**。顺带比卡的轻重：`materials[].required` 与 `questions` 少的那张优先。
5. **一个事项绑一个场景**；同事项名两种问法各召回第 1 的两个不同场景 → **拆成两个事项**。

## 三、这个技能额外的规矩（选填）

- **一行一条，段内不折行**；**只写这条线特有的护栏**（日期以今天为准、标明 AI 假设、不编造这类通用规矩页面自带）。
- **灰字示例不进包，必须自己打字。**
- 写法参照：不写绝对化用语 / 不做效果承诺 / 不写诱导分享 / 只写用户给的真实折扣 / 不替用户推断隐私标签 / 涉及预售储值提醒核对规则 / 金额日期折扣末尾提醒自己核对。

## 四、格式规范（打进 `references/format.md`）

**页面示例的形状：一类一节，每节三小点。**

```markdown
## 事项名（与常办事项逐字一致）
- 必要要素：缺了就不成立的那几样，一行列完。
- 常见错误：这个事项最容易漏、最容易写错的地方。
- 格式建议：排版与呈现口径（表格 / 分段 / 字数上限 / 可复制到 Excel）。
```

- **节数 = 常办事项条数 = 「成品结构」节数**，三者逐字对齐。
- 不写这一格，包里 `format.md` 只有占位，模型起草时容易漏条款。
- 给用户的整段粘文本，**粘之前把开头结尾那两行 ``` 去掉**。
- 末尾可附一行「场景 id 对照」表（若包内正文写了"直接带 format.md 末尾列的 scene_id"，**这段必须真存在**，否则是空指）。

## 五、改完的顺序（不能反）

① 上半页 8 格 → ② 常办事项重录（每条「试卡」验收）→ ③ 额外的规矩 → ④ 格式规范 → ⑤ 版本号 +1 → ⑥ **保存** → ⑦ **生成版本** → ⑧ 跑回归 → ⑨ 下载包 → 校验后再上传。

**顺序反了的后果**：先手工改包、后回平台点「生成版本」，重下载会把手改内容整片覆盖。

### 文件一 `编辑页逐格填写单-YYYYMMDD.md`

```
# <技能名> · 编辑页逐格填写单（YYYY-MM-DD）
> 用途：打开 <页面地址> 从上往下照着粘。
> 数据来源：场景库公开接口 <接口>（日期实测）；「用户常这么说」取自场景自带 user_expressions；召回位次用 match_scene 实测。
> 页面灰字只是示例、不会进包。

## 〇 动手前先看三处   ← 非内容格 / 上下自洽 / 事项条数与是否同一件事
## 一 上半页逐格     ← 14 行表：# | 格子 | 现在填的 | 改成 | 说明
## 二 常办事项       ← 五列表（含 scene_id 与位次）+ 每条官方原话全文
## 三 额外的规矩     ← 整段粘
## 四 格式规范       ← 整段粘（含 ``` 提示）

```
