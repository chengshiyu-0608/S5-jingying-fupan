# 硅菩提上架全流程（总控）

**这个技能不重复细节。** 六个阶段各自的写法已经在分步技能里写透了，本技能只负责三件事：**顺序**、**每一段喊谁**、**哪些地方必须停下来问用户**。

## 0. 总览

```
阶段一 选品      场景库拉数 → 判需求大 → 发布中心查重 → 出候选清单   ──▶ ⛔ 停下来：用户勾选
阶段二 定形态    技能 or 专家 / 一级分类 / 主体 / 连接器 / 包名       ──▶ ⛔ 停下来：用户确认
阶段三 填单      编辑页逐格填写单（可粘贴）→ 用户照抄进页面
阶段四 回归      写样本 → 预检 → 跑 → 分诊 → 修 → 重跑直到全过
阶段五 头像      专家＝类真人半身照；技能＝按内容出图
阶段六 出包提交  kit.mjs check → 用户本人点提交 → 记账
```

**先读这四个分步技能再做（它们的细节比这里权威）**：

| 要做的事 | 去读 | 它管什么 |
|---|---|---|
| 选品、起名、编辑页怎么填 | `guiputi-scene-selection`（v1.5.0） | 场景库接口、需求大判定、截图裁剪读法、搜索词实测表、编辑页 7.x 全字段 |
| 写回归样本、没过怎么改 | `guiputi-regression-samples` | 五字段样本、诱饵、甲~己 六类分诊、`match_scene` 预检、二b~二l 实测库 |
| 头像 | `expert-avatar-maker` | 图形版本机绘制（0 积分）、肖像版提示词、规格与体积 |
| 出包、校验、记账 | `guiputi-publish` | `kit.mjs check`、版本号、提交口径、冻结清单 |
| 端到端测别人的包 | `gptcn-skill-e2e-test` | 只测不改时用 |
| 装到本机看效果 | `wb-local-expert-install` | 侧栏「我创建的」怎么刷出来 |

**本技能自带的参考文件**：

| 文件 | 讲什么 |
|---|---|
| `references/编辑页逐格字段与粘贴模板.md` | 阶段三：逐格字段 + 两份交付模板 |
| `references/场景库接口实测.md` | 阶段一：接口层全量实测（量级、被忽略的参数、返回结构、需求信号、`user_expressions`） |

**产出根目录固定**：`D:\WorkBuddy产出\硅菩提上架\<项目名>-YYYYMMDD\`（**不放 C 盘**）。全流程所有中间脚本与日志放工作目录的 `_*.py` / `_*.txt`。

## 1. 阶段一 · 选品

> 细节：`guiputi-scene-selection` 第一节~第六节。**接口层逐条实测见 `references/场景库接口实测.md`** —— 下面带 ⚠️ 的三条是 2026-09-29 全量试跑改出来的，照字面做会返工。

1. **定线**：问清哪条线（生意线 / 行政线 / …）→ 映射场景库 `category`（生意线＝`business`）。
2. **拉全量**：`https://www.gpt.com.cn/api/scenes?limit=1000&offset=<n>`，`limit` 上限就是 **1000**。
   - ⚠️ **`category` / `cat` / `sort` / `homepage_hot` 这四个参数服务端静默忽略**（传了不报错、返回仍是默认全集）。**没有任何服务端筛选，必须全量拉下来本地过滤。**
   - 实测量级：全库 **72,016 条 → 73 次请求 → 约 2.7 分钟 → 约 50 MB**（裁字段后约 15 MB）。**只拉一次、落本地 JSON 复用**。
   - 单场景详情：`/api/scenes/<slug>` 返回 `{source, scene, generatedSpec}`，**场景对象在 `scene` 键下、不是 `items`**；想统一按 `items` 就改用 `/api/scenes?slug=<slug>&limit=1`。`/api/scene/<slug>`（单数）是 404，别用。
   - `/api/scenes?q=<词>` **固定返回 8 条**，`limit` 无效（实测确认）。
3. **判「需求大」—— 按这个顺序，别跳**：
   1. ⭐ **`identity_tags` 含 `agent_gap`**（**≡ `priority == 300`**，实测 83 个一一对应）：这是**平台自己标注的「智能体能力缺口」**，全库仅 **83 个**，business 线 **30 个**（`ag-009`~`ag-078` 那一批）。**这才是首选池。**
   2. `homepage_hot`：全库**仅 9 个**，business 线只有 1 个，多半早被占，别当主力。
   3. 分类体量 / `identity_tags` 职能标签聚簇（`demand_analyst` `new_media_operator` `ecommerce_operator` `private_domain_ops` …）。
   - ⚠️ **`priority` 没有区分度**：72,016 条里 **70,355 条都是 100**（97.7%），除 300 那一档外全是噪声。原来写的"接口排序位次"实际上等于"没排序"。
   - **接口里没有逐场景调用量，别说成"有多少人办过"。**
   - 顺手看一眼 `outputs`（`text` / `xlsx` / `png` / `docx` / `pptx`）：**文案类方向别选 `outputs=['png']` 的出图场景**；`risk_level` 为 `high` 的慎选。
4. **查重（这一步不能省；拿不到就停）**：`https://www.gpt.com.cn/admin/publish` 要登录态，agent 侧拿不到。两条路：
   - 用户给截图 → **必须裁剪放大再读**（表格行矮字小，肉眼读必错；按列分区放大 4~6 倍，裁完回读确认）；
   - 让用户在已登录页 F12 跑一次 `fetch('/api/admin/publish/assets')` 拿全表。
   - ⛔ **两条路都走不通时，停下来向用户要，不要"先做着看"**（2026-09-29 试跑实测在此卡住）。查重是这一步唯一的输出价值，跳过它整个阶段一就没有意义。
5. **出候选清单**：每个方向给「形态（专家/技能）＋ 办事单名（**≤5 字**）＋ scene_id ＋ 为什么不撞」。撞车风险看不到事项清单的，**点名最可能重叠的那个资产**写成"开做前先确认"。

⛔ **停下来**：清单交给用户**由他勾选确定**，不要自己开做。

## 2. 阶段二 · 定形态与分类

> 页面：`con.gpt.com.cn` → 「分类打包」（截图实读）。

**技能还是专家 —— 页面原话就是判据**：

> **专家数 5~30 个（一个运营专员的事），技能数 1~12 条（一件事）。**

⇒ 问自己一句：**这是在办一件事，还是在干一个岗位的活？** 一件事 → 技能；一个岗位/一类角色的全套活 → 专家。样板参照：`朋友圈社群运营`（11 件事）是**技能**；`行政证明 / 客服回复` 这类也是技能。

> ⚠️ **两个区间在 5~12 处重叠**（2026-09-29 试跑发现）：事项数落在 5~12 时，"专家数 5~30 / 技能数 1~12"**两边都成立，数值判据定不了形态**。这时候只能按"一件事 / 一个岗位"判，**别拿条数当依据**。

**一级分类选什么**（13 项，选 1~3）：

- 生意线统一 **「商业运营」**（搜索之外的第二个入口，也是发布页「市场展示分类」要填的值）；
- 办公行政线 **「办公协同」**；
- 页面另有「一级·运营·增长」这类**职能二级标签**（内容运营 / 用户运营 / 活动运营 / 社群运营 / 新媒体运营 / 私域运营 / 电商运营…），按包的实际职能勾。

**其余非内容格，动手前确认**：

| 格 | 口径 |
|---|---|
| 挂载在哪个 MCP 连接器上 | 一律「硅菩提 MCP 服务（密钥版）」；末尾「未提交」按页面提示处理 |
| 挂载在哪个主体下 | 发布后资产归属这个主体，**问用户确认**（个人 or 主体） |
| 路径名（包名 `source`） | `guiputi-` + 功能英文，全平台唯一，小写字母/数字/短横线；**改它等于另建包，一律不改** |
| 版本号 | 未提交过用 `1.0.0`；已提交过升一版；**该版号已被平台登记过 → 跳过它再升一版** |
| 服务类目 | 固定「**工具 → 办公**」（独立于上面的一级分类） |

⛔ **停下来**：把「形态 / 一级分类 / 主体 / 包名 / 版本号」列成一句话让用户确认。

## 3. 阶段三 · 填发布页，出可粘贴单

> 细节：`guiputi-scene-selection` 第七节（7.0~7.4）。**逐格字段与交付模板**见本技能 `references/编辑页逐格字段与粘贴模板.md`。

**产出两份，落项目目录**：

```
编辑页逐格填写单-YYYYMMDD.md     # 给人看：表格 + 为什么这么填 + 避坑
编辑页照抄版-YYYYMMDD.txt        # 给人抄：每格一段纯文本，段内不折行
```

**四条硬规格**（页面上都有，别记错）：

| 格 | 规格 |
|---|---|
| 技能名称（展示名） | 领域短词，**全平台唯一**，定名前先在开放平台搜一次 |
| 能力介绍 | **40–50 字**，页面实时计数；要盖住全部常办事项 |
| 触发短词 | **正好 3 个**，且**分散在三个不同的族**（示例：朋友圈 / 社群 / 会员日） |
| 试试这样问我 | **正好 3 句**，第一句是默认开场，**每句 ≤30 字** |

**常办事项（下半页第一格）—— 交付必须是四列 + 位次**：

| 事项名 | 场景名称 | scene_id | 召回位次 | 用户常这么说（整段粘，一行一条） |
|---|---|---|---|---|

- **事项名 ≤5 字**（用户 2026-09-29 明确；页面规则栏写的是 ≤6 字，按 5 字收口）。**5–30 个为宜**，别只填下限。
- **一个事项绑一个场景**；同一事项名两种问法各召回第 1 的两个不同场景 → **拆成两个事项**，别二选一。
- **「用户常这么说」抄场景自带的 `user_expressions` 原话**（`GET /api/scenes?q=<词>` 拿），每条 3~4 句，**长句照抄不要改写压缩**。**别抄场景详情页方括号里的材料清单**（那是出卡要收的材料）。
  - ⚠️ **来源常见是 6 条，不是 3~4 条**（business 线 6 条的有 10,273 个、3 条的 3,065 个）——是"从 6 条里挑 3~4 条"。
  - ⚠️ **可能是空数组**（全库 103 个场景一个原话都没有，business 里如 `video-shop-visit` 写探店视频脚本、`biz-9` 战略规划）。遇到空的从该场景 `user_task` **自拟 3 条口语问法，并在交付里标注"自拟"**，别冒称官方原话。
  - ⚠️ **同一批事项会混两种语气**：`ag-*`（agent_gap 那批）是长书面句（「帮我写一份会员运营方案，重点是怎么提高复购率。」），`leaf-*` 是超短口语（「不知道每天发啥了」）。**交付前统一一遍**：短句补主语、长句砍到 ≤20 字，否则这一栏一长一短没法看。
- **选哪个场景绑：看 `match_scene` 召回位次，不看 `?q=` 搜索命中**（两套排序经常相反）。前 2 位稳，第 3~5 位要跑一轮看，**掉出前 6 基本必挂**。
- **同时比卡的轻重要**：候选卡里 `materials[].required` 少、`questions` 少的那张优先（通用事项别绑一张要求「上传脱敏材料」的卡）。
- 事项若自带示例句（如 description 里的「客户投诉产品有瑕疵」），**主绑跟着示例句走**，近义场景 id 当备选写进 `format.md`。

**能力介绍 / 触发短词 / 试试这样问我 / 英文 4 格 —— 全是照着常办事项生成的**：事项一改，这 8 格全部重写，只改事项不改上面 = 中英不一致、内容对不上。

**「额外的规矩」**：一行一条、段内不折行，**只写这条线特有的护栏**（通用规矩页面自带）。**页面灰字只是示例不会进包，必须自己打字**。

**「格式规范」**（进 `references/format.md`）：**一类一节，每节三小点** —— `- 必要要素：` / `- 常见错误：` / `- 格式建议：`。不写这格包里只有占位，成品容易漏条款。给用户的整段粘文本要去掉包裹的 ``` 行。

⛔ **停下来**：先把「常办事项条数 + 8 格 + 规矩 + 格式规范」四块齐活的填写单交出去，**等用户抄完**再进阶段四。

## 4. 阶段四 · 回归闭环

> 细节：`guiputi-regression-samples`（尤其 §二b~§二l 的实测库与甲~己 分诊表）。

**面板口径**：每个能力包一套，**至少 3 条**，其中**至少 2 条「由它办」+ 1 条诱饵**。每条五字段：`用户会说的一句话` / `应该怎么办` / `成品里要有的词` / `成品里不许有的词` / 验收标准。

**写样本四条铁律**（都是实测踩出来的）：

1. **必须有情境**：在哪办 / 什么目的 / 自己什么情况 / 卡在哪一步想干什么。干巴巴一句话 → 模型只能吐空模板 → 判「【待填】太多，像没写」。
2. **给情境但不给抢位词**：给「商品名 + 卖点」和「用户自己的数据」；**不给**行业专有名词、商品参数清单、具体事件、具体金额。
3. **必有词只能是实体词**（材料名、章名、环节名、口径名），**绝不能是栏位名/术语**（`入职时间``岗位``收入口径``出具日期` 这类合格成品里永远不会连在一起的字）。拿不准就**把卡点写成用户的一句提问**，逼模型正面回答。
4. **「不许有的词」不填禁令词**：`format.md` 里写的「不出现返现」「不写订单号」是给模型看的禁令，**合格成品可能以提醒口吻把原词写出来** —— 填进去等于把正确答案判错。只放两类：`【待填】`（数据确实给够了时）、以及"只有真做错了才会出现"的话（诱饵填 `特此证明` 这种）。`好的，以下是` 只放文案/话术类。

**交付前必做预检**：每条「用户会说的一句话」跑一次 `mcp__guiputi__match_scene`，**目标场景要进前 2、最好第 1**。不在前 2 → **改问法，别改包**。位次表要落进产物当证据。

> ⚠️ **"进了前 2"是及格线、不是安全线**（2026-09-29 试跑实测）：3 条样本里 1 条期望场景落**第 2 位**、1 条落**第 3 位**。第 2 位也要再改一轮问法冲第 1 —— 靠"进前 2 就行"过掉，真实回归里很容易被抢位。
>
> ⚠️ **诱饵也会被真实场景抢位**：实测诱饵「帮我算一下这个月的会员复购率」召回的是「生成客户复购率分析表」「分析客户复购行为」这类**做表/分析**场景。所以诱饵的判据要写清「**不该由它办**」，同时在包里写明这类活归谁 —— 只写"诱饵"不写边界，模型仍会被召回牵着走。

**跑完回归：逐行读实况 → 分诊 → 只改该改的**（甲~己 六类见分步技能）。三条最容易走错的判断：

- **判分看「用的事项」**：期望显示 `[事项名]` = 落在事项上；显示 `[场景id]` = 这条必挂。
- **这条上一轮过、这一轮挂 → 基本是路由摇摆（戊类）**，改问法，别改包。
- **改的是哪一层，决定要不要重新生成版本**：

| 改了什么 | 要不要「生成新版本」 |
|---|---|
| 只改回归样本 | **不用**，直接重跑 |
| 编辑页任何一格（含事项名、绑的场景、规矩、格式规范） | **必须**：改 → 保存 → 生成新版本 → 再跑 |
| 包内 `SKILL.md` 正文 / frontmatter | 出下一版包，走阶段六 |

**事项名是全局最敏感的一处**：改一个字、增删一条，都会把面板里老样本的期望悬空（老选项失效 → 原本能过的条反而挂）。**只改必要的**，可改可不改的先列出来问用户。

⛔ **停下来**：每次分诊完，先把「这轮只改样本 / 还要改编辑页（那就要生成新版本）/ 要出下一版包」这句话顶在最前面说清楚，再给照抄文本。收尾轮（只剩 1~2 条）**只给那一行的整行替换补丁**，不要再出整份照抄版（用户混着抄会把旧词抄回来）。

**收口判据**：全过，或剩余项已判明是模拟机制限制（如【待填】探针纹丝不动）——此时**不许为了变绿去改包**（往规矩里塞「不许输出【待填】」是拿真实能力换分数）。

## 5. 阶段五 · 头像

> 细节：`expert-avatar-maker`。**平台规格：512×512、JPG 或 PNG、≤500 KB**（用户常要求 ≤300 KB）。

**两版的选型口径**：

| 资产 | 头像要什么 |
|---|---|
| **专家** | **类真人半身照**（半写实数字人、头肩以上到腰、浅色渐变底、无圆环无暗角）。**先问清人物形象**：男性 / 女性 / 两张都出，**不许自己替用户定性别** |
| **技能** | **按包内容出图**；图案是纯几何形（耳机 / 气泡 / 卡片 / 对勾 / 文件）→ **直接本机 `ImageDraw` 画，0 积分、无水印、免清污**，别出图 |

## 7. 跨阶段护栏（背下来）

1. **顺序不能反**：编辑页改 → 保存 → **生成版本** → 跑回归 → 下载包 → 手工改 → 压缩上传。先手工改、后点「生成版本」，重下载会把手改内容整片覆盖。
2. **冻结清单**：用户显式说要保留的内容（典型：「别删 skill 里关于下载办事卡连接器的提醒」）动手前逐条写下，**脚本里对每条加断言**（`if "硅菩提办事确认卡" not in SKILL: fail(...)`）。同源清理时最容易顺手删掉这类"看着像可选"的段落。
3. **只改必要的**：改动写成"替换/补写"，**不删节、不改节名节序**；改完列一份「改了哪几处 + 还原了哪几处 + 没动的哪几处」清单交用户。
4. **包内必须有的两条**（缺了就是 P1）：① 常办事项表**有 `scene_id` 列**，且 `format.md` 末尾**真能查到**这些 id（正文说"带 format.md 末尾列的 id"而末尾 0 个 id = 空指）；② 写清**服务端拦材料时怎么办**（卡上 `required:true` 的材料没给 → `compile_task` 硬拦 `material_missing`；包内若只写「收到就写，不要先问」就成了 P1）。
5. **数一数**：`format.md` 节数 = 常办事项条数 = 「成品结构」节数，三者对齐（平台自检也会查）。
6. **结果文件落 D 盘**，路径写死会被跨机搬不动；交付用 `present_files` 真的把文件给到用户。
7. **给用户复制用的文本绝不手动折行**：每条一整段，段与段空一行即可。
8. **不夸赞、不评价**（给上级/老板的问题反馈文档尤其）：只留 现象 → 影响 → 改法。
