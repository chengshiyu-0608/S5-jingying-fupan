## 1. 执行摘要

- 当前结论：现有版本是视觉和流程验证用单页原型，不具备正式运营所需的真实鉴权、文件解析、数据持久化、计费支付、后台、监控或合规能力。
- 本期核心交付候选：单店经营者完成“登录 → 上传或批量手填 → 数据校验 → 确认卡 → 专业报告 → 付费解锁 → 历史报告”的闭环。
- 开发阻塞项：部署区域、登录方式、支付渠道与商户资质、报告模型/API、数据留存、套餐价格、退款边界以及四类 Owner 均未获具名确认。
- 主要风险：手机号、经营流水、上传文件、订单和支付数据进入生产环境，风险等级至少 L2；错误计算可能影响用户经营决策。
- 建议下一步：业务方先确认部署区域，再依次完成支付/登录/数据策略决策；三方具名签署 Development Ready 后进入开发。

## 2. 需求概述：来源、背景与目标

### 2.1 背景与现状问题

- 目标用户是不会建立专业报表、但需要快速看懂“赚没赚、问题在哪、明天做什么”的小微门店经营者。
- 现有原型已经验证营销首页、案例、上传/手填入口、确认卡、报告信息架构和套餐布局的表达方向，但所有关键业务动作仍为浏览器本地模拟。
- 若直接发布，用户可能误以为短信、文件、分析和付款已经真实生效，且经营数据无法获得生产级保护、恢复与审计。
- 已知约束：不得使用 Emoji；图标使用 SVG；界面需自然、专业、易懂；R1 聚焦单店闭环，不扩张为重型 ERP。

## 7. 详细功能需求

### FR-001 登录与会话

- 来源与业务价值：SRC-001、GAP-001；为用户数据、订单和报告建立真实身份边界。
- MVP 现状与证据：EVD-002，任意 4 位验证码即可进入。
- 目标行为：按最终选型支持手机号验证码、微信授权或组合登录；会话可撤销、过期、限流并记录安全事件。
- 页面入口与可见条件：营销页“开始复盘”、结算和历史报告受保护入口。
- 加载 / 空 / 错误 / 无权限状态与恢复：发送中、验证码错误、过期、频率限制、账户禁用均有明确恢复路径。
- 状态与数据副作用：创建用户、身份绑定、会话和登录审计；不在日志记录完整验证码。
- 权限：未登录仅访问公共内容；用户仅访问本人资源。
- 优先级：Must
- 依赖：DEC-001、DEC-003、短信或微信开放平台资质。
- Owner：产品 Owner + C 技术负责人（均待任命）
- 状态：待确认

AC-FR-001-01

```gherkin
Given 用户身份凭据有效且账户未禁用
When 用户完成所选登录方式的服务端验证
Then 系统创建有过期时间的安全会话并进入数据导入页
And 登录事件包含用户标识、方式、时间和结果但不包含验证码明文
```

AC-FR-001-02

```gherkin
Given 同一身份或设备达到发送频率限制
When 用户再次请求验证码
Then 系统拒绝请求并展示可重试时间
And 不创建新验证码且记录风控事件
```

### FR-002 安全上传与对象存储

- 来源与业务价值：SRC-001、GAP-002；允许无系统对接的小微门店提交真实账本。
- MVP 现状与证据：EVD-004，仅选择本机文件并套用示例数据。
- 目标行为：支持已批准格式的 Excel、CSV 和图片；服务端签发上传凭据，完成大小、扩展名、MIME、病毒和内容校验后写入隔离对象存储。
- 页面入口与可见条件：登录后的数据导入页；同时保留批量手工表格录入。
- 页面元素：文件列表、校验进度、失败原因、替换/删除、示例模板下载。
- 状态与数据副作用：upload.created → scanning → ready / rejected；记录文件哈希、Owner、大小和保留策略。
- 权限：仅文件 Owner 和受权后台角色可访问；使用短时签名 URL。
- 优先级：Must
- 依赖：DEC-001、DEC-005、对象存储和恶意文件扫描服务。
- Owner：C 技术负责人 + 安全/数据 Owner（待任命）
- 状态：待确认

AC-FR-002-01

```gherkin
Given 已登录用户选择一个符合批准格式和大小限制的文件
When 上传、哈希校验和安全扫描完成
Then 系统将文件状态标记为 ready 并允许创建解析任务
And 其他普通用户无法通过猜测 URL 读取该文件
```

AC-FR-002-02

```gherkin
Given 上传文件的真实 MIME 与扩展名不符或扫描结果为风险文件
When 服务端完成校验
Then 系统将文件标记为 rejected 并展示可理解的失败原因
And 文件不得进入解析队列且安全事件被审计
```

### FR-003 解析、字段映射与数据质量检查

- 来源与业务价值：SRC-001、GAP-003；避免用户手算损耗率并支持多品类、成百上千条流水。
- MVP 现状与证据：EVD-004，文件内容未被读取。
- 目标行为：异步解析 Excel/CSV/图片；映射日期、品类、商品、数量、售价、成本、折扣、退款、损耗等标准字段；输出缺失、重复、异常值和 OCR 置信度问题。
- 页面入口与可见条件：文件 ready 后自动或由用户发起。
- 页面元素：字段映射、质量分、问题筛选、批量修正、原值对照和解析日志编号。
- 分支 / 异常 / 恢复：部分行失败不丢弃整份文件；用户可修正映射后基于同一原文件重跑。
- 状态与数据副作用：原文件只读；每次解析产生独立版本、标准化行和问题清单。
- 权限：继承文件资源权限。
- 优先级：Must
- 依赖：标准字段字典、OCR/解析器选型、黄金样本集。
- Owner：数据 Owner + C 技术负责人（待任命）
- 状态：待确认

AC-FR-003-01

```gherkin
Given 文件包含标准字段和多种商品流水
When 解析任务成功完成
Then 系统生成标准化数据集、字段映射和质量检查结果
And 每一标准化行可追溯到原文件、工作表和原始行或图片区域
```

AC-FR-003-02

```gherkin
Given 必填字段缺失或图片字段置信度低于批准阈值
When 解析任务结束
Then 系统将数据集标记为 needs_review 并列出具体问题
And 在用户修正和确认前不得生成正式报告
```

### FR-004 确认卡与分析口径版本化

- 来源与业务价值：SRC-001、GAP-004；把“点点选选确认卡”保留为专业分析前的责任边界。
- MVP 现状与证据：EVD-007，有确认卡 UI 意图但无版本和审计。
- 目标行为：展示门店、周期、数据范围、币种、成本口径、退款/折扣/损耗处理和待修正问题；确认后冻结输入版本，后续修改创建新版本。
- 页面入口与可见条件：数据集完成解析且至少存在可用行。
- 页面元素：摘要、问题数、口径选项、批量修正、确认声明和差异预览。
- 状态与数据副作用：保存确认人、确认时间、口径版本、字段修改前后值。
- 权限：资源 Owner 可确认；后台代处理需展示身份并留审计。
- 优先级：Must
- 依赖：FR-003、指标字典、业务规则确认。
- Owner：产品 Owner + 数据 Owner（待任命）
- 状态：待确认

### FR-005 经营指标计算与诊断规则引擎

- 来源与业务价值：SRC-001、GAP-005；输出比用户自行加减更专业、可解释和可复算的经营诊断。
- MVP 现状与证据：EVD-004，分析结果为示例硬编码。
- 目标行为：基于版本化指标字典计算营业额、销量、成本、毛利额、毛利率、客单价、折扣、退款、损耗和品类贡献；用差异分析定位数量、价格、结构、成本和损耗变化。
- 页面 / 接口：Analysis API 和内部规则配置；前台显示口径、公式说明和证据行。
- 分支 / 异常 / 恢复：分母为零、缺少上期、数据覆盖不足时输出“不可计算 + 原因”，不得伪造趋势。
- 状态与数据副作用：保存规则版本、输入版本、输出快照和计算日志摘要。
- 权限：仅消费已确认数据集。
- 优先级：Must
- 依赖：业务批准的指标字典、FR-004。
- Owner：数据 Owner + 产品 Owner（待任命）
- 状态：待确认

AC-FR-005-01

```gherkin
Given 固定的 confirmed 数据集、指标字典版本和测试期望值
When 规则引擎执行两次
Then 两次基础指标和差异分解结果完全一致
And 每个数值包含口径版本和可追溯输入引用
```

AC-FR-005-02

```gherkin
Given 数据缺少可比较期间或某指标分母为零
When 系统生成分析结果
Then 对应指标显示不可计算及具体原因而不是零或虚构百分比
And 报告任务仍可为其他有效指标生成结果
```

### FR-006 专业报告生成、版本与下载

- 来源与业务价值：SRC-001、GAP-006；把确定性指标组织成专业复盘报告和三项可执行行动。
- MVP 现状与证据：EVD-004，使用 setTimeout 展示固定报告。
- 目标行为：异步生成报告预览和完整报告；至少包含执行摘要、数据质量、核心指标、趋势/结构、利润变化原因、异常与证据、三项行动、口径与免责声明；支持网页查看和版本化 PDF 下载。
- 页面入口与可见条件：数据集 confirmed；完整内容按权益解锁。
- 页面状态：排队、生成中、预览可用、完整可用、失败、重试中、已过期。
- 分支 / 异常 / 恢复：AI 解释失败时允许降级到规则模板；基础指标不得受生成模型影响。
- 状态与数据副作用：保存报告版本、生成器版本、模型/提示版本引用、输入快照、权益和下载审计。
- 优先级：Must
- 依赖：FR-005、DEC-004、FR-007。
- Owner：产品 Owner + C 技术负责人（待任命）
- 状态：待确认

### FR-007 套餐、订单、支付回调与退款状态

- 来源与业务价值：SRC-001、GAP-007；建立真实可对账的商业闭环。
- MVP 现状与证据：EVD-005，价格硬编码且付款不扣款。
- 目标行为：展示经批准的套餐版本；由服务端创建订单和支付请求；验签处理回调、主动查询、关闭和对账；退款能力是否首发由 DEC-007 决定。

## 11. 安全、隐私与合规

- 数据分类与信任边界：手机号、微信标识、原始账本、经营流水、订单和报告均按敏感业务数据处理；浏览器、API、对象存储、解析器、模型服务和支付渠道之间建立明确边界。
- 认证与授权：安全会话、CSRF/重放防护、资源级授权、后台最小权限；高风险操作重新认证或审批。
- 输入与文件：扩展名、MIME、大小、压缩炸弹、宏、恶意内容和 OCR 输入攻击防护；解析在隔离环境运行。
- 密钥与加密：密钥不入仓库；生产 Secret 通过专用管理；传输加密、存储加密和日志脱敏方案由技术与安全评审。
- 模型安全：默认不把无必要的原始文件发送给生成模型；供应商、数据出境、训练使用和删除承诺需书面核验。
- 隐私权利：收集前告知目的和范围；支持导出、删除和撤回；留存最小化，规则由 DEC-005 决定。
- 合规：是否需要 ICP/公安备案、隐私政策、用户协议、支付协议及具体适用法规取决于 DEC-001 和运营主体，必须由具名法务/合规负责人确认。
- 供应链：锁定依赖版本，生成 SBOM，核验开源许可证；禁止将当前 CDN development runtime 直接带入生产。
