# 生意线五个精品网页 Skill 源审计与实施建议

核验日期：2026-10-08  
目标：为“商品与定价、进货与库存、营销与获客、会员与复购、经营复盘”五个精品网页筛选高质量 Skill 来源，并明确哪些内容可以借鉴、哪些内容不能直接带入 WorkBuddy 技能包。

## 一、先给结论

建议采用“开源方法论 + 硅菩提适配层”的方式，不直接把市场技能或 GitHub 仓库原文打包发布。

首期最值得深挖的来源是：

1. `anthropics/knowledge-work-plugins` 的 small-business 技能：结构完整、带 references、明确连接器与 CSV 兜底，最适合做网页流程骨架。
2. `alirezarezvani/claude-skills`：定价、采购、财务分析、市场调研的方法较完整，适合作为计算口径和问题清单的补充。
3. `wondelai/skills`：留存、转化、精益分析、经营改进，适合作为会员复购和经营复盘的诊断框架。
4. `minhnv0807/ai-business-skills`：营销文案、活动复盘、推荐计划等场景丰富，适合作为内容与活动工作台的模板素材。

不建议把公众号、媒体文章作为核心 Skill 源码来源。媒体内容可以用于补充用户语言、案例和行业观察，但不能替代 GitHub 源码、许可证和可运行性核验。

### 1. 商品与定价

重点借鉴：价格结构、成本拆解、目标毛利、保本销量、试卖验证和“停止继续投入”的边界。

必须改造：

- 把 SaaS、融资、B2B 合同报价改成小摊位、小门店、轻量线上经营的商品语境。
- 允许用户只提供商品名、进货价、包装/损耗、目标售价和预计日销量；缺少成本时进入材料闸门。
- 不把“爆款”当成事实，必须区分用户提供的数据、公开观察和模型假设。
- 产出必须有数字表，不只给一段定价建议。

### 2. 进货与库存

`inventory-planner` 是五个网页中最适合直接做精品化的上游骨架。它明确区分 7 天速度和 28 天基线，计算缺货日期、补货量、在途库存和慢动销，并要求审批后才形成采购动作。

必须保留的规则：

- 库存数量必须带“截至日期”。
- 缺货期间的零销量不能当成零需求。
- 零动销商品不能被推荐继续补货。
- 补货量要扣除在途库存，并显示金额、包装起订量和舍入方向。
- 没有可靠历史时，不生成伪造的缺货日期。

网页首期不宣称已接入 Shopify、Square、NetSuite；应支持手填、CSV 或盘点照片转录。采购单和供应商消息必须经过用户确认，不自动发送。

### 3. 营销与获客

`social-content-engine` 的价值不在“自动发帖”，而在于把一次商品事实转成连续内容：内容日历、统一口吻、渠道改写和人工审批。

硅菩提版本应增加：

- 朋友圈、社群、小红书、门店公告、海报和现场话术的渠道选择。
- 每条内容绑定商品、价格、活动时间、适用人群和行动入口。
- 输出“可直接复制版”和“发布前检查单”。
- 图片只先生成海报 brief、尺寸和文案安全区；没有图像连接器时不声称自动生成成图。
- 促销建议要同时显示原价、优惠价、成本底线和有效期。

### 4. 会员与复购

`review-reputation` 提供了“原话证据—主题归类—逐条回复—沉默客户识别—召回草稿”的闭环；`improve-retention` 和推荐计划技能可补充复购机制。

必须改造成个体户可执行的轻量版本：

- 会员分层先用最近一次消费、消费频次、金额和偏好，不做复杂 CRM 标签树。
- 支持微信好友、微信群、到店优惠券和会员日等实际触点。
- 每次召回最多给一小批可执行名单，避免输出几百人的空泛表格。
- 召回话术必须引用真实消费或偏好；没有真实记录只能输出“待补事实”的草稿。
- 不自动群发、不自动发优惠券，不承诺接入微信或第三方 CRM。

### 5. 经营复盘

`report-builder` 适合做网页的“可保存复盘定义”：用户描述一次报表后，系统保存指标、公式、分组、比较周期和数据来源，下次可重复运行。`cash-flow-snapshot` 补充现金安全和 30/60/90 天视角，`lean-analytics` 补充“只改一个变量”的实验纪律。

首期复盘页应围绕小微经营者的五个问题：

1. 今天/本周卖了多少？
2. 扣掉进货、包装、平台和损耗后还剩多少？
3. 哪个商品、时段或渠道异常？
4. 异常最可能由什么事实造成？
5. 明天只做哪一个动作，何时回来复盘？

不建议首期做跨系统“全景经营脉搏”：上游版本依赖大量账务、CRM、支付和日历连接器，容易把连接器能力误写成网页自身能力。

### 完整性检查结果

- `inventory-planner`：`SKILL.md` + 5 个 reference，包含数据源、速度与补货、季节性、采购单和常见陷阱。
- `social-content-engine`：`SKILL.md` + 6 个 reference，包含日历、渠道改写、发布流程与示例。
- `review-reputation`：`SKILL.md` + 5 个 reference，包含来源、主题、回复模式、流失信号和示例报告。
- `report-builder`：`SKILL.md` + 5 个 reference，包含数据源、报告规格、保存定义、输出模板和常见陷阱。
- `cash-flow-snapshot`：`SKILL.md` + 3 个 reference，包含数据源、陷阱和 worked example。
- `restock`：有完整 `SKILL.md`，但它把采购与应付账款、付款记录串起来；首期只复用补货决策与审批闸门，不照搬财务连接器链路。

### 安全与外部依赖结论

- 本轮未发现需要写入技能包的密钥、Token 或私有凭证。
- 上游技能主要是说明文档，`allowed-tools` 多为 `Read, WebFetch`，不是本地可直接调用的 WorkBuddy 连接器。
- Shopify、Square、NetSuite、QuickBooks、Canva、Google/Yelp/Facebook 等均属于上游可选连接器，不能在硅菩提技能包中写成“已接入”。
- 所有连接器都要有 CSV/手填/粘贴文本兜底，并在成品中写清数据来源和日期。

## 四、市场技能库的取舍

### 可以作为候选的市场技能

- 商品卖点提炼、做定价、爆款商品分析：并入“商品与定价”网页，不再各自做独立网页。
- 算进货量、做库存盘点、采购比价分析：并入“进货与库存”网页。
- 促销活动文案、店铺公告文案、门店引流方案：并入“营销与获客”网页。
- 会员运营方案、老客户召回：并入“会员与复购”网页。
- 产品指标复盘、数据分析、数据可视化、数据看板 HTML：并入“经营复盘”网页。

### 不应直接收进精品网页的候选

- 需要实时广告、CRM、地图、支付或社交平台权限的技能：先做文件输入版。
- 企业级项目管理、多人审批、HR、法务、金融和复杂 ERP 场景：超出当前小微经营定位。
- 只有泛泛建议、没有可下载/可复制成品的技能：降级为知识卡，不进入精品工具入口。
- 与已有卖货文案、小红书、朋友圈社群、客户异议处理、门店专家重复的技能：做网页聚合，不重复打包。

## 五、WorkBuddy 技能包的适配规则

每个精品网页对应的技能包都应自行重写以下部分：

1. **用户对象**：个体户、摊位、小门店和轻量线上经营者。
2. **事实输入**：手填、CSV、照片转录或确认卡；缺关键事实就停在材料闸门。
3. **确认卡**：先列用户事实、模型假设、缺口和将要生成的成品，再询问确认。
4. **成品格式**：至少一个可复制或可下载成品；例如 XLSX、报告、清单、话术包或海报 brief。
5. **人工审批**：采购、发布、群发、优惠和付款动作均不能自动执行。
6. **历史版本**：保存数据日期、口径、成品版本和下一步，支持回到之前记录。
7. **来源说明**：包内放 `THIRD_PARTY_NOTICES.md` 和许可证文件；不把外部仓库原文伪装成原创。

平台发布页还要满足：能力介绍控制在 40—50 字；触发短词正好 3 个；“试试这样问我”正好 3 句；常办事项带 `scene_id`；编辑页检查提示不能原样打入最终包。

## 六、推荐开发顺序

### 第一批（先做精品网页）

1. **进货与库存**：输入字段清楚、计算可验证、XLSX 交付明确，最适合先做真实回归。
2. **经营复盘**：复用已有“门店经营数据诊断”定位，增加可保存的报表定义和历史版本。
3. **商品与定价**：与库存和试卖计划连接，但保持独立成品。

### 第二批

4. **营销与获客**：先支持内容包、活动表和海报 brief，后续再考虑图片生成或平台连接。
5. **会员与复购**：等有真实消费记录字段后再做名单级召回，避免生成空泛 CRM 表。

## 七、下一步不是继续找更多 Skill，而是做三项确认

1. 确认五个网页是否采用上表的主 Skill 组合。
2. 先确定“进货与库存”网页的输入字段、计算口径和 XLSX 成品模板。
3. 确认是否允许保留 Apache-2.0/MIT 来源声明；确认后再分别建立五个自有 Skill 包和回归样本。

在这三项确认前，不建议直接下载或复制更多市场技能，也不建议把公众号文章直接写进技能包。
