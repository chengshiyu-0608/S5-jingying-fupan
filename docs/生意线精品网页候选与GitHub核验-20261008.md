# 生意线精品网页候选与 GitHub 核验

核验日期：2026-10-08  
范围：硅菩提底座后台场景库、生意线已有能力包、本地上游 GitHub 快照  
目的：筛出能交付真实成品、需求信号明确、交付链路短、适合做精品网页的生意场景；本轮只读调研，不修改后台、不提交上架。

## 一、先给结论

第一期不建议继续做一个“大而全的生意专家包”。已有的小微经营助手和门店经营专家已经覆盖路线框架、开店、引流、活动、算账、复盘等大类；再做一个总专家会产生召回竞争和能力重叠。

更适合的产品形态是：

> 一个小微经营工作台，下面挂 5 个能单独交付成品的精品网页模块；每个模块再绑定底座中的 1—3 个明确场景。

推荐先做以下 5 个网页模块：

1. **库存与补货决策台**：盘点 → 算进货量 → 补货清单 → 慢动销提醒，输出 XLSX/清单。
2. **门店经营数据诊断**：流水、成本、客流、客单、复购拆解，输出诊断报告与明日动作；沿用已有“销售漏斗分析”定位，不再另起同名包。
3. **老客复购与会员运营**：会员方案、老客召回、触达话术、复购记录，输出执行 SOP/内容表。
4. **门店内容与活动工作台**：卖点、促销、店铺公告、朋友圈/小红书内容，输出可直接复制的多渠道内容包；与已有新品推广原型合并能力，不另做重复的“小红书工具”。
5. **选品与定价决策台**：货—人—场匹配、试错成本、毛利/保本、进货边界，输出选品表、定价表和试卖计划；沿用已有 S2 成本与定价工作，不另建泛化“选品专家”。

第二期再评估：选址与证照、供应商比价、口碑与投诉、短视频/海报物料。它们有价值，但要么依赖地区政策或实时资料，要么与已做能力重叠，先不要占用第一期网页入口。

### GitHub 核验结论

1. 上述 8 个技能的 `SKILL.md` 与引用文件均在本地快照中，链接检查未发现缺失文件。
2. 上游多数技能依赖外部 MCP；适配 WorkBuddy 时必须把“连接器可用”和“CSV/手填兜底”分开写，不得声称已经接入 Shopify、QuickBooks、Canva 或评论平台。
3. 最适合先做网页的不是“业务快照”本身，而是有明确输入—计算—导出的 `inventory-planner`、`social-content-engine`、`report-builder` 三类结构。
4. 复用上游思想时保留 Apache-2.0 许可证和第三方声明，新增的确认卡字段、场景映射和小微经营规则要作为硅菩提适配层单独维护。

## 六、建议的精品网页结构

### 1. 入口层：按经营问题进入，不按 Skill 名称进入

首页只展示 5 个高频入口：

- 今天该补什么货？
- 这家店到底赚不赚钱？
- 老客怎么再回来？
- 这周发什么、做什么活动？
- 这个品该不该卖、卖多少钱？

每个入口都先选经营形态（流动摊位/固定摊位/小门店/线上），再进入确认卡；已完成节点允许跳过，但保留“重新评估”。

### 2. 工作流层：一页只完成一个结果

统一为：

`选择目标 → 补齐事实 → 确认卡 → 计算/生成 → 复核 → 导出 → 记录下一步`

禁止把 5 个模块拼成一个长表单。每一步都应显示：用户提供事实、AI 假设、缺失材料、最终成品和下一动作。

### 3. 成品层：优先真实可下载/复制的产物

| 模块 | 首期成品 |
|---|---|
| 库存与补货 | XLSX 盘点表 + 补货清单 + 慢动销清单 |
| 门店经营诊断 | 诊断报告 + 口径表 + 明日只改一件事 |
| 老客复购 | 会员分层表 + 召回批次 + 触达话术 |
| 内容与活动 | 多渠道文案包 + 活动执行表 + 发布检查单 |
| 选品与定价 | 选品比较表 + 成本/毛利/保本表 + 试卖计划 |

## 七、网页化验收标准

一个候选只有同时满足下列条件，才进入精品网页开发：

- 有明确的 `scene_id`，且主问法能在召回前 2 位；
- 真实输入不足时能停在材料闸门，不用大量 `【待填】` 伪装成成品；
- 至少有一种可下载或可复制的成品结构；
- 不依赖未接入的 CRM、支付、地图、广告或社交平台；
- 结果能被用户在当天执行或发出；
- 能记录版本、数据日期和下一次复盘入口；
- 与现有能力包有清晰边界，不争抢同一事项；
- 至少准备 3 条正向回归样本和 1 条诱饵样本，再做平台回归。

## 八、下一步执行顺序

1. 用户确认是否采用 P0 五个网页模块。
2. 先为“库存与补货决策台”确定字段和成品模板；它最容易用真实 CSV/手填数据验证，且输出 XLSX 明确。
3. 并行把“门店经营数据诊断”改成最终名称，沿用已通过的销售漏斗分析能力，不创建新重复包。
4. 对每个模块做查重：事项名、`scene_id`、已上架包、已有网页入口四项都要留记录。
5. 只对用户确认的前 2 个模块做 GitHub 深适配、确认卡字段、回归样本和网页原型；其余先不打包。

## 九、本轮未做的事项

- 未修改底座场景、发布页或已有能力包。
- 未运行付费平台回归，也未提交 WorkBuddy。
- 未把 GitHub 连接器当成当前环境已安装能力。
- 未把后台优先级解释成真实调用量或转化率。

## 十、关键修正：不是把 13,976 个场景做成 13,976 个网页

这些数是底座“生意线”目录记录，不等于 13,976 个独立产品需求。标题相近、不同渠道/行业模板、不同输出格式、以及与个体经营无关的商业/企业场景都混在其中。若一条场景配一页，会造成页面海量重复、用户找不到入口、开发和回归不可维护。

### 建议的网页数量与承载方式

| 层级 | 建议规模 | 是什么 | 页面形态 |
|---|---:|---|---|
| 网站固定页面 | 6—8 页 | 首页、场景库、工作台/我的生意、成品编辑与导出、历史记录、帮助/资料等 | 真正人工打磨的产品页面 |
| 一级场景分类 | 6 个 | 开店筹备；选品与定价；采购与库存；获客与成交；内容与活动；经营分析与复购 | 分类导航，不单独做成 6 套产品 |
| 首期可用工作流 | 5 个 | 库存补货、经营诊断、老客复购、内容活动、选品定价 | 每个工作流一个高完成度工具页/流程页 |
| 首期场景卡 | 30—50 个 | 每个工具页下的清晰任务，如“算进货量”“写店铺公告”“分析门店流水” | 数据驱动的场景卡，不是单独网页 |
| 可搜索长尾场景 | 先收录 100—300 个，验证后扩展 | 按行业/渠道/经营阶段/输出物做可组合模板 | 同一套详情模板动态呈现；搜索、筛选、推荐 |
| 未筛选底座记录 | 13,976 个 | 原始候选池，含低相关、重复、行业专用或工具依赖场景 | 不直接进入网站；在后台维护为待筛选素材 |

规模是产品规划建议，不是声称已从 13,976 条中完成逐条人工审核。首批 30—50 个可用场景需要逐个过查重、材料门槛、真实成品和回归；长尾 100—300 条先按搜索需求逐批开放。

### 场景库导航：让用户按“我要解决什么”找，而不是背技能名

一级入口控制在 6 类：

1. **准备开起来**：方向判断、选址观察、证照材料、开店预算。
2. **把货选对、价格算清**：商品比较、卖点、定价、毛利、保本、试卖。
3. **进货与库存**：供应商比价、盘点、进货量、补货、损耗、慢销。
4. **让顾客来并买单**：门店引流、活动、现场话术、售前售后、团购。
5. **内容与宣传**：朋友圈、小红书、短视频、海报、公告、卖货文案。
6. **看经营、做复购**：流水诊断、日复盘、会员、老客召回、评价处理。

页面顶部保留一个自然语言搜索框（如“我想知道这个月到底赚没赚钱”）；下面用经营阶段、经营形态、行业、渠道、交付物、所需材料做筛选。用户无需先理解底座 taxonomy。

### 13,976 条如何筛选成可用场景

先逐条过滤候选，而不是按标题关键词直接收录：

1. **经营者范围**：保留个体户、摊位、小门店、轻量线上经营可完成的任务；排除企业级管理、工程技术、HR/法务/金融等与主线无关项。
2. **单一用户目标**：一条记录只能对应一个清楚的问题与一个主要结果；把“全流程方案/经营咨询/增长策略”拆到可执行任务，近义项合并。
3. **可交付成品**：必须明确输出文本、表格、报告、图片 brief 或可执行清单；只有空泛建议、强依赖外部连接器、需要不可验证实时数据的先降级或排除。
4. **输入可获得**：所需数字/图片/记录必须能通过用户手填、上传 CSV/照片或确认卡获得；缺关键材料要明确暂停，不得编造。
5. **不重复现有资产**：与门店专家、排班、开闭店检查、朋友圈社群、小红书笔记、卖货文案、客服回复、直播话术、确认卡已有销售模块等逐项查重；相同任务只保留一个入口。
6. **可验证**：每个首期场景至少有 3 条正向回归和 1 条不应处理的诱饵样本；交付结构能检查，才进入“可用”。

### 一个场景记录，不等于一个页面

每条保留的长尾场景只需保存为结构化数据：

`scene_id / 用户说法 / 经营阶段 / 生意目标 / 适用经营形态 / 输入材料 / 交付类型 / 使用的网页工作流 / 已有资产归属 / 风险等级 / 回归状态`

网页按同一个模板渲染不同场景。只有需要专属计算器/图形编辑器/复杂数据导入的工作流才做定制交互页。例： “盘点库存”“算进货量”“安全库存建议”共享“库存与补货决策台”，并不是三页；“朋友圈促销文案”“店铺公告”“小红书笔记”共享“内容与活动工作台”，只切换输出模板。

### 首期页面草图

```text
首页：我现在想解决什么？（搜索 + 5 个高频任务）
  └─ 场景库：6 个一级分类 + 筛选/搜索/最近使用
       └─ 场景详情：适用人群、要准备什么、会得到什么、样例成品
            └─ 工作流：填写/上传 → 确认 → 生成 → 修改 → 导出
                 └─ 我的经营记录：按项目/日期保存结果、版本和下一步
```

因此第一期要做的是“5 个深工作流 + 30—50 个经过验收的场景卡 + 同一套长尾目录模板”，不是数万张页面。扩展长尾时只增加场景数据和模板，不按场景数量线性增加开发成本。

## 十一、按分类做精品：推荐的产品架构

如果你的目标是“分类做精品”，建议把生意线收口成 6 个精品工作台。每个工作台不是一个大而空的专家，而是一个围绕同一经营问题的网页；网页下面挂 3—6 个旗舰工作流，再把同类长尾场景作为场景卡、模板和搜索结果承载。

### 6 个精品分类

| 分类 | 用户要完成的生意目标 | 首批精品工作流 | 推荐首批场景 |
|---|---|---|---|
| 1. 开店准备与合规 | 能不能开、在哪里开、要准备什么 | 选址评估；开店预算；证照材料清单 | `biz-14` 选址开店；`dp-yjs-29` 餐饮证照；`new-jcxgcgp7gzy8` 开店成本 |
| 2. 选品与定价 | 卖什么、卖给谁、卖多少钱 | 选品决策；成本毛利；套餐/价格测试 | `promo-14` 选品分析；`new-y2rlz43msef4` 做定价；`biz-pricing-analysis` 产品定价分析；`ag-017` 爆款商品分析 |
| 3. 采购与库存 | 买多少、何时补、哪些货不能再买 | 库存盘点；进货量计算；安全库存/慢销提醒 | `new-us1474z6b3sw` 库存盘点；`new-vpezuolj41z4` 算进货量；`leaf-1hbvnas` 安全库存动态表；`ag-072` 采购比价 |
| 4. 内容营销与活动 | 让附近的人看见、愿意到店或咨询 | 卖点与卖货文案；朋友圈/小红书内容；活动物料 | `biz-sell-copy` 卖货文案；`ag-009` 卖点提炼；`ag-013` 促销活动文案；`ag-014` 店铺公告；`video-douyin-talk` 抖音口播 |
| 5. 获客与成交 | 顾客来了以后怎么介绍、报价、处理犹豫 | 门店引流；售前咨询；现场异议与售后 | `ag-026` 门店引流；`ag-010` 售前咨询；`ag-011` 售后安抚；已有客户异议处理包 |
| 6. 经营分析与复购 | 今天赚不赚、下次改什么、老客怎么回来 | 门店经营诊断；每日复盘；会员/老客召回 | `fin-store-revenue-analysis` 门店流水；`leaf-iyoh7w` 经营分析报表；`ag-025` 会员运营；`ag-020` 老客户召回；`leaf-1n007q5` 复购率分析 |

### 精品数量控制

建议按以下规模建设：

| 阶段 | 分类数量 | 每类精品工作流 | 总精品工作流 | 每个工作流挂载的场景卡 |
|---|---:|---:|---:|---:|
| 第一阶段 | 6 | 2 个旗舰 | 12 个 | 3—5 个 |
| 第二阶段 | 6 | 4 个 | 24 个 | 5—15 个 |
| 稳定期 | 6 | 5—6 个 | 30—36 个 | 按搜索和真实使用扩展 |

所以你最终不是做几万个网页，而是做 **6 个分类、30 个左右精品工作流、约 100—300 个经过验收的场景卡**。底座的几万条记录只是候选素材库。

### 分类页的统一结构

每个分类页只保留以下区域：

1. 分类说明：这类工作台解决什么问题。
2. 旗舰工具：展示 2—6 个可直接开始的精品工作流。
3. 常见任务：场景卡列表，按“我想算账/我想写文案/我想补货”等用户说法呈现。
4. 行业筛选：小吃饮品、零售、生活服务、农产品、线上经营等。
5. 经营阶段筛选：准备开始、试营业、稳定经营、调整经营。
6. 交付物筛选：表格、报告、文案、清单、图片方案。
7. 最近使用与历史版本：让用户找回之前做过的成品。

### 精品工作流的统一模板

每个精品工作流都使用同一套页面骨架，不再为每个场景单独设计页面：

```text
输入经营事实 → 缺失材料提示 → 确认卡 → 生成成品 → 用户修改 → 导出/复制 → 保存版本 → 下一步建议
```

例如“采购与库存”分类里：

- “库存盘点”是盘点模板；
- “算进货量”是计算模板；
- “安全库存动态表”是预警模板；
- 三者共用上传/手填商品数据、确认、导出和历史记录页面。

### 分类精品化的筛选规则

每条底座场景进入某个精品分类前，必须通过 7 项筛选：

- 用户对象符合个体户、小摊贩、小门店或轻量线上经营者；
- 能归入一个分类和一个明确工作流；
- 只有一个主要交付目标；
- 输入材料能由手填、上传或确认卡获得；
- 产出是可复制、可下载或可执行的成品；
- 不与已有技能/专家重复；
- 至少有 3 条正向回归样本和 1 条诱饵样本。

不通过的场景放入“待筛选素材库”，不在网站首页展示；行业过窄、依赖实时连接器、需要专业资质判断或只有泛泛建议的场景，不进入精品层。

### 最终建议

产品导航采用：

`6 个分类 → 12 个首期旗舰工作流 → 30—50 个首批场景卡 → 搜索/筛选扩展长尾`

第一批优先开发：

1. 采购与库存；
2. 经营分析与复购；
3. 选品与定价；
4. 内容营销与活动；
5. 获客与成交；
6. 开店准备与合规。

这样既能覆盖开店前、经营中、经营后的完整链路，又不会把网页做成几万个入口。
